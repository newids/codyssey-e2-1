## 1. MVP가 증명해야 하는 것

기능 목록이 아니라 **증명 명제**로 범위를 정한다. 아래 세 가지를 3분 데모 안에서 보여주지 못하면 MVP 실패다.

| # | 명제 | 증명 장면 |
|---|---|---|
| P1 | 강의 없이 미션만으로 학습이 된다 | 심사위원이 직접 모의 이체를 완수하고, 막혔을 때 답이 아닌 힌트를 받는다 |
| P2 | AI가 사람에 따라 실제로 다르게 가르친다 | 같은 사기 경고가 60대·20대 프로파일에 다른 형식으로 출력되는 화면을 나란히 시연 |
| P3 | 공공데이터로 "실익이 있는 학습"이 돌아간다 | 몇 가지 질문에 답하면 실제 받을 수 있는 지원금 후보가 나온다 |

전략적 함의: P2가 차별화의 핵심이므로 **적응형 프롬프트가 최우선 구현 대상**이다. UI 완성도는 P2를 가리지 않는 선에서만 투자한다.

## 2. 범위 (In Scope)

### 2-1. 미션 1 — 이체 시뮬레이션

- 실제 뱅킹 앱을 본뜬 모의 UI (가상 계좌·가상 잔액). 실제 금융 시스템 연결 없음.
- 과제: "OO에게 3만 원 보내기". 완료 조건: 수취인·금액 확인 화면까지 도달.
- **3단계 힌트 사다리** (자기주도 원칙 — 답을 주지 않는다):
  1. 방향 제시: "보내려면 먼저 어떤 메뉴가 필요할까요?"
  2. 위치 힌트: "화면 아래쪽 버튼들을 살펴보세요"
  3. 직접 안내: 해당 버튼 하이라이트
- 힌트 요청 빈도·소요 시간은 문해 프로파일 갱신 신호로 사용.

### 2-2. 미션 2 — 사기문자 판별 퀴즈

- 문자 3건 제시, 사기 1~2건 포함. 사용자가 사기를 지목.
- 오답·정답 모두 **판별 근거 해설** 출력: "발신 번호가 실제 기관 번호와 다릅니다 / 기관은 앱 설치를 요구하지 않습니다."
- 해설 컴포넌트는 프로파일에 따라 형식이 달라진다 (P2와 동일 엔진).
- 세그먼트별 문항 세트: 고령층(권위 순응형 기관사칭 중심) / 청년층(악성앱·명의도용 중심).

### 2-3. 미션 3 — 지원금 찾기 대화

- 대화형 질문 3~5개(연령대·거주지·근로 상태 등)로 상황 파악 → 지원금 후보 2~3건 제시.
- 데이터: 보조금24 API 연동이 목표이나, **API 승인 전에는 주요 지원금 30건 정적 스냅샷으로 폴백** (데모 품질 동일, §7 리스크 참고).
- 신청서 작성 동행은 범위 밖 — 후보 제시 + 신청 경로 안내까지만.

### 2-4. 온보딩 — 문해 수준 진단

- 질문 2~3개(스마트폰 뱅킹 사용 경험, 선호 설명 방식) + 첫 미션 행동 신호(힌트 빈도, 응답 시간)로 프로파일 구성.
- "진단 테스트"처럼 보이지 않게 — 대화 형태로 30초 이내.

## 3. 적응형 AI 설계

### 3-1. 문해 프로파일 스키마

```
profile {
  literacy_level: 1 | 2 | 3     // 1=초심자, 3=능숙
  pace: slow | normal | fast
  format: step-by-step | summary-card   // 단계별 vs 요점 카드
  large_text: boolean
  voice_assist: boolean          // Web Speech API (선택 기능)
}
```

### 3-2. 적응형 프롬프트 구조

- 단일 시스템 프롬프트 템플릿 + 프로파일 주입 방식. 파인튜닝 없음 (비용·기간 최소화).
- 난이도별 출력 규칙을 프롬프트에 명시: 문장 길이 상한, 어휘 수준(전문용어 사용 여부), 한 번에 제시하는 단계 수, 형식(카드/번호 단계).
- 검증 방법: 동일 입력("기관사칭 문자 경고")에 프로파일 1·3을 각각 주입한 출력을 나란히 비교 — 이것이 곧 **비교 데모 화면**(백로그 4번)이 된다.

### 3-3. 모델·비용

- LLM API 호출(적응형 해설·대화). 판별 퀴즈 해설은 **사전 생성 후 캐시** — 데모 지연·비용·심사장 네트워크 리스크를 동시에 제거.
- 실시간 호출은 미션 3 대화와 자유 질문에만 사용.

## 4. 사기문자 판별 데이터셋

- **출처**: 금감원·경찰청 「보이스피싱지킴이」 공개 피해사례 (fss.or.kr, 민원·신고 > 보이스피싱지킴이). 원문 전재가 아니라 **수법 패턴을 추출해 재작성** — 개인정보·저작권 리스크 차단, 실제 기관명·전화번호는 가상화.
- **스키마**: `id / 유형(기관사칭·대출빙자·지인사칭·악성앱) / 타깃 세그먼트 / 본문 / 판별 단서 목록 / 난이도(1–3)`
- **규모**: 1차 30문항 (유형 4 × 난이도 3 × 2~3문항). 판별 단서 라벨은 수작업 작성·상호 검수.
- 근거 통계와 정합: 기관사칭형이 전체의 51%(경찰청, 2025)이므로 기관사칭 문항 비중을 40% 이상으로.

## 5. 범위 밖 (Out of Scope — 의도적 제외)

| 제외 항목 | 이유 | 복귀 시점 |

| 학습 이력 서버 저장 | 개인정보 리스크 제로 원칙 (보안성) | 파일럿 |
| 동료 멘토링 매칭 | 4050 AI Cafe 오프라인 파일럿으로 대체 검증 | 파일럿 |
| 실전 사기 판별 모드 | 오판 리스크 — 훈련 모드 데이터셋 검증 먼저 | 2단계 |
| 청소년·중장년 트랙 | 고령층·청년 2개 세그먼트로 시작 | 2단계 |
| 음성 안내(TTS) | 선택 기능 — 브라우저 Web Speech API로 저비용 시도, 안 되면 즉시 제외 | 여유 시 |

## 6. 기술 스택·배포

- **프론트**: React 기반 웹앱 1종 (모바일 우선 반응형 — 고령층 데모는 태블릿/폰 화면 기준).
- **백엔드**: 서버리스 함수 1개 (LLM API 프록시 — 키 노출 방지). DB 없음.
- **상태**: 로컬 스토리지 (프로파일·미션 진행).
- **배포**: Vercel 또는 Railway (서버리스 함수 필요 — GitHub Pages 정적 호스팅으로는 불가).
- **오프라인 폴백**: 캐시된 사전 생성 응답으로 네트워크 없이 데모 완주 가능하게.

## 9. 성공 기준 (측정 가능)

1. 데모 완주: 온보딩 → 미션 2 → 비교 데모를 3분 이내, 조작 실수 없이.
2. 적응형 식별률: 베타 테스터 10명 중 8명 이상이 프로파일 1·3 출력을 블라인드로 "다른 대상용"으로 구분.
3. 해설 정확도: 30문항 전체에서 AI 판별 해설의 사실 오류 0건 (수작업 전수 검수).
4. 베타 피드백: 4050 AI Cafe 5명 이상 실사용 피드백 확보.
5. 오프라인 데모: 네트워크 차단 상태에서 미션 2 완주 가능.
