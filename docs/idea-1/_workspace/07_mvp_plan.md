# MVP 구축계획서 v1.0 — 금융 코디세이

> 작성일: 2026-08-20 | 작성: mvp-builder | 상태: 작업본(발행 예정 경로 `docs/idea-1/MVP_구축계획서_v1.0.md`)
> 현재 상태 표기: **금융안전 영역 판별 실습 · 정적 프로토타입**

금융 코디세이는 사용자가 금융과업을 수행하는 행동 데이터로 금융역량을 진단하고,
그 진단 결과를 API로 금융회사·공공기관에 공급하는 플랫폼이다.
학습과 실습은 진단을 만들어 내는 수단이자 진단 결과의 출력물이며, 우리가 파는 것은 진단이다.

이 계획서는 그 플랫폼 중 **지금 무엇이 실제로 작동하고, 무엇이 아직 아닌가**를 파일 단위로 밝히고, 다음 4단계에서 무엇을 어떤 완료 기준으로 만들 것인지를 정한다. 이 문서는 작동하지 않는 것을 작동하는 것처럼 쓰지 않는다.

**지금 작동하는 것을 한 문장으로:** 사용자가 3문항으로 프로파일을 만들고 → 행동수칙 4개를 보고 → 사기·정상 문자 9건을 판별하고 → 프로파일에 맞춘 해설을 받고 → 자극 유형별 취약도 지수와 1회차 대비 개선폭을 확인하는 회차 반복 루프가, 브라우저 안에서 끝까지 돈다.

**설계가 코드와 결속된 지점.** 금융안전 취약도 지수는 문서상의 산식이 아니라 실행되는 함수다. 반감기 가중(기본 3회차), 최소 노출 3건 미만은 `측정 중` 표기, 코호트 최소 인원 30명 미만 미산출(재식별 방지)이 전부 단위 테스트로 고정돼 있다. 기관 리포트는 합성 데이터 전용 모듈에서만 값을 받고 화면에 `예시 데이터(합성)` 배지를 항상 노출한다 — 실사용 기록과 합성 값이 코드 경로에서 분리돼 있다.

## 2. 갭 분석과 목표 정의

### 2-1. AI 3기능 × 3영역 매트릭스 (9칸)

| | 기초금융 | 금융안전 | 생활금융 |
|---|---|---|---|
| **금융역량 진단** | 지표 정의 완료 · 미구현 | **구현됨** (취약도 지수 + 회차 개선폭) | 지표 정의 완료 · 미구현 |
| **AI 가이드형 실습** | 미설계 | 규칙 경로만 구현 · **LLM 경로 미구현** | 미설계 |
| **개인별 학습경로 추천** | 미설계 | 부분 구현(영역 안에서 다음 회차 집중 유형 선택) | 미설계 |

**9칸 중 온전히 채워진 칸은 1칸이다.** 이 표를 숨기지 않는 것이 이 계획서의 존재 이유다. 심사자가 물을 질문은 "AI가 있느냐"가 아니라 "그 AI가 지금 어디서 돌고 있느냐"이며, 정직한 매트릭스와 그것을 메우는 일정표가 가장 강한 답이다.

### 2-2. 갭 4건 (우선순위 순)

1. **런타임 LLM 호출 0건.** 적응형 해설은 데이터셋의 판별 단서를 프로파일별로 다르게 조립한 규칙 출력이다. 프롬프트·기준 문안·비교 스크립트는 만들어져 있으나 실행된 적이 없다. **AI 3기능 중 ②가 문서에만 있다는 뜻이며, 이것이 최대 갭이다.**
2. **진단이 3영역 중 1영역뿐.** 3축 금융역량 프로필을 말하면서 실제로 산출되는 축은 금융안전 1축이다.
3. **연결 루프가 닫혀 있지 않다.** 다음 회차의 집중 자극 유형은 취약도에 따라 자동 선택되지만, 그것이 「학습경로 추천」으로 사용자에게 제시되지도, 수용 여부가 계측되지도 않는다.
4. **정적 배포 형태.** 서버가 없어 키를 숨길 곳도, 진단 결과를 API로 내보낼 자리도 없다. 프로필은 기기 밖으로 나가지 않는다(개인정보 측면에서는 장점, 사업 구조 측면에서는 미구현 구간).

### 2-3. 목표 — 각 기능을 어디까지 작동시킬 것인가

「지금 동작하는 규칙 경로」와 「데이터가 쌓인 뒤의 고도화 경로」를 항상 함께 밝히는 서술 규율을 코드에도 그대로 적용한다. **규칙 경로는 언제나 살아 있어야 한다** — LLM 경로는 그 위에 얹히는 층이지 대체물이 아니다.

| 기능 | 규칙 경로 (현재) | 이번 계획의 도달선 | 계획 범위 밖 |
|---|---|---|---|
| **금융역량 진단** | 금융안전 취약도 지수 산출 | 3영역 각각의 영역 점수 산출 + 비합산 3축 프로필 최초 산출 | 축적 데이터 기반 분류·회귀 학습 |
| **AI 가이드형 실습** | 데이터셋 단서의 프로파일별 조립 | 오답 해설 1경로를 실제 LLM 호출로 생성 + 근거 문구 부착 + 실패 시 규칙 폴백 | 음성 안내 · 시나리오 자동 생성 · 대규모 검색 근거 |
| **학습경로 추천** | 다음 회차 집중 자극 유형 자동 선택 | 최저 영역 우선 + 최근 회차 가중으로 다음 학습 제시, 수용률 계측 | 순위 학습 모델 |

**M1 완료 기준 5조 (판정 대상).**
1. 오답 해설 1경로가 실제 모델 호출로 생성되어 화면에 표시된다.
2. 프로파일 2종(초심자/능숙)에서 **같은 판단 근거가 다른 전달 방식으로** 출력된다 — 기준 문안의 구조 규칙(안심 문장으로 시작·3단계 이내·전문용어 없음 / 카드 1장·결론 먼저)에 수렴하는지 대조한다.
3. **API 키가 클라이언트 번들에 존재하지 않는다** — 빌드 산출물 전수 문자열 검사로 확인한다.
4. 호출 실패·지연·상한 도달 시 **현행 규칙 해설로 자동 전환**되고 사용자 화면은 중단되지 않는다.
5. 안전 가드가 출력에 적용된다 — 금융상품 추천·투자 권유·개인 금융정보 재질문 차단, 확신이 서지 않으면 판단 유보.

**일정 정렬.** 08-28 게이트 판정 → 통과 시 09-07 마감 공모전에 M1까지의 결과물과 데모를 제출하고, 불통과 시 M1 기한을 09-14로 늦춰 10-08 마감 공모전에 M1+M2를 넣는다. **이것은 실패가 아니라 사전에 정의한 분기다.**

**선행 조건 1건(사용자 판단 필요).** 현행 MVP 구축 규칙 문서는 「런타임 LLM 호출 없음」을 고정 원칙으로 두고 있다. M1은 이 원칙을 **부분 해제**해야 착수할 수 있다(해설 1경로에 한정, 규칙 폴백 상시 유지). 규칙 문서 개정 없이는 M1을 시작하지 않는다.

## 4. 진단 설계 구현 — 3영역 공통 프레임의 코드 매핑

공통 프레임 4단은 `금융 과업(미션)` → `관측 행동 신호` → `규칙 채점` → `영역 점수(0~100)`이며, 세 영역이 같은 뼈대를 공유한다.

| 영역 | 미션(M3 최초 1종) | 관측 행동 신호 | 채점 | 코드 |
|---|---|---|---|---|
| 기초금융 | 가상 이체 1건 완수 | 과업 완수 여부 · 소요 단계 수(최소 경로 대비) · 오조작 횟수 · 중도 이탈 지점 | 과업별 규칙 채점 → 가중 평균 | 신규 모듈 |
| 금융안전 | 판별 실습(현행) | 사기 시나리오를 정상으로 판정 ÷ 발송 건수, 자극 유형별 | 취약도 지수, 영역 점수 = 100 − 지수 | **기존 모듈 · 로직 무변경** |
| 생활금융 | 지원제도 조건 매칭 1건 | 조건 해석 정확도 · 문서 이해 정답률 · 정보 탐색 소요 단계 | 과업별 규칙 채점 → 가중 평균 | 신규 모듈 |

**비합산을 코드로 강제한다.** 프로필 조립 함수는 세 영역 각각에 `점수 또는 null`과 `측정 상태`를 담은 객체를 돌려주고, **총점 필드를 아예 두지 않는다.** 합산이 필요해지는 순간이 오면 그것은 요구사항 변경이지 계산 편의가 아니다 — 총점은 취약 영역을 평균으로 가리고, 그 순간 진단-연결 구조가 또 하나의 점수로 전락한다.

**추천 규칙.** 다음 학습은 `최저 영역 우선 + 최근 회차 가중`으로 정하고, 동점이면 노출이 적어 아직 `측정 중`인 영역을 먼저 채운다. 측정된 영역이 하나도 없으면 금융안전 진단 회차를 기본값으로 제시한다.

**한계.** 기초금융·생활금융의 신호별 가중치는 실사용 데이터 없이 확정할 수 없다. 초기값은 **운영 기본값**이며 조정은 시범 적용 이후다. 반감기 3회차·최소 인원 30명도 마찬가지로 운영 기본값이고, 최소 인원은 상향만 한다. 이 사실을 화면과 문서 양쪽에서 숨기지 않는다.

## 5. 데이터 확보 계획

**현행 40문항이 선례다.** 공개된 사기 사례의 **수법 패턴만 추출해 전면 재작성**했고 원문 전재가 없다. 전화번호는 0000 계열, 링크는 `*.example` 계열 가상 표기이며, 자극 유형 라벨은 모델이 붙이지 않고 **사람이 검수해 고정**했다. 정상 문항 10건을 섞어 오탐(정상을 사기로 판정) 측정이 가능하게 했다. 확장 문항도 같은 규칙을 그대로 적용한다.

| 항목 | 현재 | 필요량·계획 |
|---|---|---|
| 금융안전 문항 | 사기 30(이득 8 · 공포 6 · 친밀 6 · 권위 5 · 긴급 5) · 정상 10 | 3회차 반복 시 자극 유형 1종당 최대 9건이 소모된다 → **유형당 9건 이상, 사기 45건 이상**으로 증량. 기관사칭 소재 비중 40% 유지(기관사칭형이 전체 피해의 51% — 부록 출처 [5]) |
| 기초금융 미션 | 없음 | 가상 은행·가상 계좌 화면 1종 자체 제작. 실계좌·실거래 접근 없음 |
| 생활금융 미션 | 없음 | 공공서비스(혜택) 정보 API(부록 출처 [20])를 소스로 설계. **활용신청 미완**이므로 확보 전에는 가상 샘플 10건으로 구현하고, 실연동을 주장하지 않는다 |
| 설계 근거 자료 | 경찰청 CSV(부록 출처 [7]) 확보 | 세그먼트·문항 구성비 산정에만 사용 |
| 참고 자료 | 디지털정보격차 실태조사(부록 출처 [9]) | **공공저작물 제2유형(출처표시·상업적 이용금지)** — 설계 참고용 한정, 재배포하지 않는다 |
| 근거 검색용 자료 | 없음 | 공식 금융자료·공공정보만 대상. 외부 수집분은 **1차 자동 검증과 사람 검수를 함께 거친 뒤** 적재한다 |

## 6. 검증 방법

| 층 | 방법 | 현재 | 확장 |
|---|---|---|---|
| 순수 로직 | 단위 테스트 | 52케이스 통과 | M1에서 폴백·프롬프트 조립·가드 케이스, M3에서 영역 점수·추천 케이스 추가 |
| 화면 | 정적 렌더 스모크 | 6케이스 | 추천 화면·3축 표시 추가 |
| 적응형 출력 | 동일 입력을 프로파일 2종으로 호출해 **기준 문안 대비 구조 대조** | 미실행(키 미설정) | M0에서 1회 실행, M1에서 구조 규칙 자동 점검 스크립트로 승격 |
| 루프 | 회차 반복 통합 테스트 | 3케이스 | 진단→추천→재측정 폐루프로 확장 |
| 효과 | **사전 진단 → 실습 → 사후 재진단의 3측정** 설계 | 지표 4종이 이미 코드로 계산됨 | 시범 적용 시 수집 |
| 예산 | 빌드 출력의 gzip 크기 | 60.92 KB / 80 KB | 상한 유지 |
| 발행 | 배포본 문자열 검사 | 수동 | 게이트 항목으로 고정 |

우리는 효과를 숫자로 약속하지 않는다. 대신 효과를 측정하는 방법을 제출한다.
1단계 PoC에서 사전 진단 → 실습 → 사후 재진단의 3측정 설계로
취약도 개선폭·판별 정확도·행동수칙 준수율을 수집하고, 그 결과가 기대효과 수치의 최초 근거가 된다.
현재 제시할 수 있는 것은 측정 가능한 지표의 정의와 산출 방법이며, 그중 네 개는 이미 코드로 계산된다.

코드로 이미 계산되는 네 지표는 **취약도 개선폭 · 판별 정확도와 오탐률 · 행동수칙 준수율 · 집단 단위 개선 리포트(합성 데이터 기준)**이고, 추천 수용률은 M2에서, 과업 완수 지표는 M3에서 계산 가능해진다.

## 7. 아키텍처 진화 경로

```
[현행]  브라우저(React 정적) ── 로컬 저장소
              외부 호출 없음

[M1]    브라우저 ──▶ 최소 API 서버(1라우트) ──▶ LLM
          │              키 보관 · 호출 상한 · 출력 가드
          └── 응답 실패 시 규칙 해설로 자동 전환(항상 살아 있음)

[M2~]   브라우저 ──▶ API 서버 ──▶ LLM
                        └──▶ 프로필 저장소(가명처리 · 동의 · 보유기간)
```

| 항목 | 설계 |
|---|---|
| **서버 범위** | 라우트 1개(`해설 생성`)로 시작. **무상태** — 요청은 문항 본문과 프로파일 요약만 받고 식별자를 받지 않으며 저장하지 않는다. 정적 앱은 그대로 GitHub Pages에 남고 서버만 분리 호스팅한다 |
| **키 관리** | 서버 환경변수로만 주입. 저장소·클라이언트 번들·로그에 남기지 않으며, 빌드 산출물 문자열 검사를 발행 게이트에 넣는다 |
| **비용 통제** | 호출당 토큰 상한(입력·출력 모두 상한 지정), 세션당 호출 3회 상한, 일일 총 호출 상한, 월 예산 상한. **단가는 미확인**이므로 금액을 문서에 쓰지 않고 호출량 상한으로 통제한다 |
| **레이트리밋** | 클라이언트별 분당 상한 + 서버 전역 상한. 상한 도달 시 오류가 아니라 **규칙 해설로 전환**하고 화면에 지연 사유를 알리지 않는다(사용자 경험 중단 금지) |
| **안전 가드** | 입력면: 사용자 자유 입력을 모델에 넘기지 않고 **데이터셋 문항과 프로파일 값만** 전달해 주입 표면을 최소화한다. 출력면: 금융상품명·투자 권유·개인정보 요구 표현을 걸러 위반 시 규칙 해설로 대체. 판정 이력을 기록해 사후 추적이 가능하게 한다 |
| **개인정보 변화** | 현행 = 기기 밖으로 나가는 데이터 없음. M1 = 식별자 없는 단발 요청(저장 없음). M2 = 저장 시작 시점부터 **가명처리**, 수집 항목·목적·보유기간 고지와 동의를 화면에 둔다. 기관 제공 결과는 집계 단위로만 산출하고 최소 인원 미달 집단은 산출하지 않는다 |

## 8. 일정 · 리스크 · 축소 경로

### 8-1. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| LLM 통합이 기한 내 동작하지 않음 | 게이트 불통과 | 8-2의 축소 사다리로 단계 하강. 규칙 경로는 항상 살아 있으므로 앱 자체는 무사하다 |
| 호출 비용 초과 | 예산 소진 | 호출 상한 3중(세션·일·월), 상한 도달 시 자동 폴백. 데모는 사전 생성 결과로 진행 |
| 응답 지연 | 시연 중 정지 | 타임아웃을 짧게 잡고 초과 시 즉시 규칙 해설. 시연 경로는 캐시 우선 |
| 환각·부정확 안내 | 신뢰 훼손 | 판단 근거를 데이터셋 단서로 고정하고 모델은 **전달 방식만** 담당. 근거 없는 단정 금지, 확신 없으면 판단 유보 |
| 키 노출 | 계정 오남용 | 서버 전용 보관 + 빌드 산출물 문자열 검사 + 호출 상한 |
| 공모전 요강 미확인 | 제출물 형식 불일치 | **미확인** 상태를 유지하고, 확인 즉시 어댑터 층에서만 대응. 공통 코어는 형식 중립으로 유지 |
| 공공데이터 활용신청 미완 | 생활금융 미션 지연 | 가상 샘플로 먼저 구현. 실연동 주장을 하지 않는다 |
| 개발 자원 | 전 단계 지연 | M1을 라우트 1개·화면 1곳으로 좁혀 최소화. M2 이후는 마감이 늦은 공모전 일정에 배치 |

### 8-2. 축소 사다리 (마감 임박 시 위에서 아래로 하강)

1. **완전 경로** — 런타임 호출 + 근거 부착 + 폴백 + 가드.
2. **호출 축소** — 오답 해설 1경로에만 호출, 나머지는 규칙 경로.
3. **사전 생성** — 문항 × 프로파일 조합의 해설을 **빌드 시점에 미리 생성해 정적 자산으로 포함**한다. 산출물은 모델 생성 결과이되 런타임 호출은 0으로 돌아간다. 이 경우 문서에는 「사전 생성 방식」임을 명시한다.
4. **비교 결과 제출** — 앱은 현행 그대로 두고, 동일 입력에 대한 프로파일별 출력 비교표를 별도 자료로 제출한다.
5. **현행 유지** — 정적 프로토타입 그대로 제출하고 구현 범위를 정확히 표기한다.

**3단 이하로 내려가면 어떤 문서에서도 「런타임 AI가 동작한다」고 쓰지 않는다.** 축소는 허용되지만 표기 왜곡은 허용되지 않는다.

### 8-3. 코드 작업 금지 사항 (전 단계 공통)

- 취약도 지수의 계산 로직을 바꾸지 않는다(파라미터 조정은 운영 기본값 범위에서만).
- 학습자 화면의 쉬운 말 문안을 임의로 바꾸지 않는다.
- 기관 리포트의 `예시 데이터(합성)` 배지를 제거하지 않는다.
- 최소 인원 30명 미만 미산출 규칙을 완화하지 않는다.
- 데이터셋의 가상 전화번호·가상 링크 표기를 훼손하지 않는다.
- 은퇴한 명칭 체계(모듈 번호·컴포넌트 식별자·구 사업 명칭)를 코드나 문안에 도입하지 않는다.
- 용어집 밖의 제3의 표기를 만들지 않는다.
