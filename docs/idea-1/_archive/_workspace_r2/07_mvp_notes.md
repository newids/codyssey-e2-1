## 3. 화면 흐름 변경

```
[변경 전]  intro → onboarding(3문항) → quiz(3라운드) → 해설 → result
[변경 후]  intro → onboarding(3문항) → ★briefing(대응 수칙 4개) → quiz(3라운드) → 해설
                → result(점수 + ★취약도 막대 + ★회차 델타 + ★공유 카드) → ★기관 리포트 미리보기
                     └→ "N+1회차 훈련하기" → briefing 으로 되돌아 순환
```

- **세션 구성 변경(`src/lib/quiz.js`).** 기존 `buildRounds`(라운드당 사기 1~2건, 유형 무관)를 `buildSession`으로 교체했다. 한 세션 = 3라운드 × 3건 = **사기 6건(자극 유형 2종 × 3건) + 정상 3건**. 유형당 3건을 고정한 이유는 지수 산출 조건 n≥3을 한 세션 안에서 채워야 결과 화면이 `측정 중`만 띄우지 않기 때문이다. 라운드별 사기 개수는 무작위(1~3)로 흔들어 "매번 2개 고르면 된다"는 요령이 생기지 않게 했고, 라운드 안내 문구도 "1개일 수도 2개일 수도"에서 "몇 개가 사기인지는 알려 드리지 않습니다"로 바꿨다.
- **집중 노출(`selectFocusLures`).** 1회차는 진단으로 권위·공포(기관사칭형이 몰려 있는 두 자극)를 쓰고, 2회차부터는 **가장 취약한 측정 유형을 1순위**로 유지(1회차 대비 개선폭을 계속 볼 수 있게)하고 2순위는 아직 측정되지 않은 유형에 배정해 측정 범위를 넓힌다.
- **피격 판정.** 판별 퀴즈형이므로 규칙은 하나다 — **사기 문항을 지목하지 못하면 피격**(`roundExposures`). 링크 클릭·정보 입력 경로는 이 형태에 존재하지 않는다.
- 시니어 프로파일의 큰 글씨·단계별 전달, 정상 문항 혼입(오탐 훈련), 해설의 근거 동일성은 그대로 유지된다.

## 5. MVP 단순화 — 전략과의 의도적 차이(기록)

전략을 어긴 것이 아니라, 정적 퀴즈형에 담기 위해 축약한 지점이다. 심사 질문이 들어올 수 있으므로 명시해 둔다.

| # | 단순화 | 이유 |
|---|---|---|
| 1 | 한 세션이 자극 유형 2종만 다룬다 | 유형당 최소 노출 3건(n≥3)을 3라운드 안에서 채우기 위함. 나머지 3종은 화면에 `측정 중`으로 남아 오히려 최소 표본 규칙을 눈으로 보여 준다 |
| 2 | 1회차 진단 유형을 권위·공포로 고정 | 피해 구성비 1위인 기관사칭형이 이 두 자극에 몰려 있다. AI 프로파일링이 아닌 고정 규칙 |
| 3 | 개인 화면의 개선폭도 "패널 고정" 원칙을 적용 | 1회차와 최신 회차 **모두에서 산출된 유형**만 델타를 낸다. 코호트 규칙(§3-6a 정의 3)을 개인 단위에 그대로 옮긴 형태 |
| 4 | 반응률(열람÷발송) 미표시 | 퀴즈형은 열람률이 100%로 고정 — 전략 §3-6a "MVP에서의 축약" 지시 그대로 |
| 5 | 기관 리포트는 합성 데이터 전용 화면 | 실사용자 코호트가 존재하지 않는다. 실데이터와 합치는 코드 경로 자체를 두지 않았다 |

## 6. 대외 표기 확인 (proposal-writer · deck-producer용 사실 확인)

전략 §⑨ D5의 표기 규칙과 **현재 구현이 일치**한다. 문서에 쓸 때 아래 사실과 어긋나면 구현 기준으로 맞춰 주기 바란다(문서를 이 노트가 고치지는 않는다).

- 대외 표기: `판단형 미션 실습 프로토타입(정적) — 사전 수칙·취약도 지수 포함`.
- **구현됨:** 대응 수칙 사전 교육 / 프로파일별 적응형 해설 / 규칙 기반 채점 / 취약도 지수(자극 유형별·최근 회차 가중·최소 노출) / 회차 델타 / 결과 공유 카드 / 기관 리포트 미리보기(합성).
- **미구현(계속 미구현 목록에 유지):** 취약 자극 유형 진단(AI) · 시나리오 자동 생성 · 음성 출력.
- 주의해야 할 문장 하나 — MVP 화면의 자극 유형 값은 **사람이 검수해 고정한 라벨 + 규칙 기반 집계**의 결과다. MVP를 설명하면서 "AI가 취약 유형을 진단한다"고 쓰면 구현과 어긋난다. AI 진단은 본 서비스 설계(향후)의 요소로만 서술할 것.
- 합성 데이터 화면을 스크린샷으로 쓸 경우 **배지가 보이는 상태**로 캡처해야 한다(전략 §⑪-6).
