## 2. 학습자 표면 무변경 확인

전략 §⑨ D5 "손대지 않는 것" 목록을 문자열 단위로 대조했다. **소스 diff 기준 학습자 표면 변경 0줄**이며, 빌드 산출물에서도 원문 그대로 검출된다.

| 학습자 표면 | 문자열 | 번들 검출 |
|---|---|---|
| 온보딩 3문항 | `스마트폰으로 은행 일…` | 유지 |
| 행동수칙 브리핑 본문 | `먼저, 대응 수칙 4가지` + 규칙 4개 | 유지 |
| 라운드 안내 문구 | `몇 개가 사기인지는 알려 드리지 않습니다` | 유지 |
| 결과 화면 지표 제목·설명 | `자극 유형별 취약도`, `취약도 = (최근 회차에 …)` 산식 1줄 | 유지 |
| 측정 상태 표기 | `측정 중` | 유지 |
| 공유 카드 | `[모의사기 훈련 결과]`, `이 카드는 훈련 결과 공유일 뿐 금융 판단의 조언이 아닙니다.` | 유지 |
| 합성 데이터 배지 | `예시 데이터(합성)` | **변경 금지 대상 — 유지** |
| 해설(적응형) | `src/lib/adaptive.js` 문안 전체 | 유지 |

- 결과 화면의 `이 값은 기관 리포트에서 집계 단위로만 쓰이며…` 문장은 **학습자용 지표 설명**이므로 §⑦-16에 따라 치환하지 않았다. 은퇴 문자열 전수 검색(§⑪-3)의 대상은 제출 계층 문서이며, 이 문장은 `집계 리포트`가 아니라 `기관 리포트`이고 학습자 표면이라 양쪽 규칙 모두에 걸리지 않는다.
- 공유 카드의 `[모의사기 훈련 결과]`는 방법 명칭(`모의사기 훈련`)이 존치 대상(§8-14 A-1 비고)인 데다 학습자 표면이라 이중으로 유지 사유가 있다.
- 코드 주석·모듈 내부 식별자(`cohortDemo.js` 등)는 표면이 아니므로 손대지 않았다 — 화면 문자열 diff를 3줄로 유지해 검증 비용을 낮추는 쪽을 택했다.

## 5. 관측 사항 (judge-redteam 판정용 — 문서를 직접 고치지 않음)

1. **`mvp/web/index.html`의 `<title>`은 이번 범위에 없어 손대지 않았다.** 전략 §⑨ D5 표가 지정한 파일은 `App.jsx`·`CohortReport.jsx`·`Result.jsx` 3건뿐이고, `<title>`·메타에 정식 표제를 넣는 지시는 D3(기획서 웹)에만 있다. 앱 `<title>`까지 정식 표제 대상으로 볼지 판단이 필요하면 별도 지시를 받아 처리한다.
2. **MVP 화면에는 정식 표제(`AI 기반 전기통신금융사기 대응역량 훈련 체계`)가 등장하지 않는다.** 헤더는 상용 계열의 축약 표기(`대응역량 훈련 프로토타입`)이며, 이는 전략이 지정한 문자열 그대로다. 제출 문서가 "MVP 화면에 정식 표제를 노출한다"고 서술하면 구현과 어긋난다.
3. **MVP 기능·산식은 v1.3 상태 그대로다.** §3-6a 산식, `피격`·`발송`·`측정 중` 용어, 취약도 지수 순수 함수와 단위 테스트 11케이스는 v1.4에서 치환 금지 대상이므로 변경이 없다. 구현된 것/미구현인 것의 목록도 직전 라운드와 동일하다(미구현: 취약 자극 유형 진단(AI)·훈련 시나리오 자동 생성·음성 출력).
4. 대외 표기가 `판단형 미션 실습 프로토타입(정적)` → `판별형 훈련 모듈 실습 프로토타입(정적)`으로 바뀌었으므로, 제출 문서에서 MVP를 부를 때 옛 표기(`미션`)가 남지 않았는지 문서 측 전수 검색이 필요하다(코드에는 해당 문자열이 없다).
