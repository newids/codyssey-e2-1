# 데모 시나리오 스크립트 v0.1 — "같은 경고, 다른 전달"

> 작성일: 2026-08-15 | 기준: MVP_스코프_v0.1.md §1(P2)·§3, 기획서_초안_v0.1.md §3-4
> 용도: 공모전 본선 발표(3분 시연 구간) + 베타 테스트 안내 대본
> 원칙: 문자 예시의 기관명·전화번호·URL은 전부 가상. 실존 번호·도메인 사용 금지.

---

## 1. 이 데모가 증명하는 것

**P2: AI가 사람에 따라 실제로 다르게 가르친다.**

- 형식: 좌우 분할 화면 1개(권장) 또는 기기 2대 나란히. 왼쪽 = 67세 프로파일, 오른쪽 = 24세 프로파일.
- 심사위원이 확인하게 되는 것: **입력은 동일, 판단 근거도 동일, 전달만 다르다** — 적응형 UX와 설명가능성을 한 장면에서.
- 소요: 3분 (타임라인 §6).

## 2. 등장 프로파일 (데모용 페르소나)

| | 왼쪽 화면 — "순자 님" | 오른쪽 화면 — "지훈 님" |
|---|---|---|
| 나이/상황 | 67세, 스마트폰 뱅킹 6개월차 | 24세, 취준생, 디지털 능숙 |
| literacy_level | 1 | 3 |
| format | step-by-step (한 번에 한 단계) | summary-card (요점 카드) |
| large_text | true | false |
| voice_assist | true (음성 낭독) | false |
| 취약 패턴 | 권위 순응형 기관사칭 (60대 이상 피해 비중 30.6%, 경찰청 2025.9) | 악성앱·명의도용 (기관사칭형 피해자 중 30대 이하 52%, 2025) |

## 3. 입력 — 동일한 사기 문자 1건

기관사칭형(전체 피해의 51%, 경찰청 2025)을 대표 시나리오로 선택. 두 화면에 **완전히 동일한 문자**가 도착한다.

```
[검찰청 통지] 귀하 명의의 계좌가 금융범죄 사건에
연루되어 출석요구서가 발부되었습니다.
사건 확인 및 소명자료 제출: hxxp://check-case77.example
미확인 시 계좌 동결 조치됩니다.
문의: 02-000-0000 (가상)
```

판별 단서 (두 화면 공통의 판단 근거):
1. 검찰·경찰·금감원은 문자로 사건을 통보하지 않는다
2. 링크 접속·앱 설치 요구 = 악성앱 유도
3. "계좌 동결" 등 시간 압박·공포 조성은 전형적 수법
4. 회신 번호로 걸면 안 됨 — 실제 기관 대표번호를 직접 찾아 걸어야 함

## 4. 출력 스크립트 — 오른쪽 화면 (지훈, 24세)

카드 1장, 한 화면에 전부. 기본 글씨 크기.

```
⚠️ 사기 확률 매우 높음 — 검찰 사칭 스미싱

왜 사기인가
• 검찰은 문자로 사건을 통보하지 않음 (100%)
• 링크 = 악성앱 설치 유도. 누르면 원격제어 위험
• "계좌 동결" 협박은 전형적 압박 수법

지금 할 일
차단·삭제하면 끝. 확인이 필요하면 검찰청
대표번호를 직접 검색해서 전화 (문자 속 번호 금지)

이미 링크를 눌렀다면 → [긴급 대처 보기]
```

## 5. 출력 스크립트 — 왼쪽 화면 (순자, 67세)

큰 글씨, 한 번에 한 단계, [다음] 버튼으로 진행, 각 단계 음성 낭독.

**단계 1 / 3**
```
이 문자는 사기입니다.

놀라지 않으셔도 됩니다.
아직 아무 일도 일어나지 않았습니다.
계좌도 안전합니다.

        [ 다음 ▶ ]
```

**단계 2 / 3**
```
검찰은 문자를 먼저 보내지 않습니다.

진짜 검찰이라면 우편으로 보냅니다.
문자 속 파란 글씨(인터넷 주소)는
절대 누르지 마세요.

        [ 다음 ▶ ]
```

**단계 3 / 3**
```
지금 하실 일은 한 가지입니다.

이 문자를 지우세요.

마음이 불안하시면 가족에게
이 화면을 보여주시거나,
검찰청 대표번호로 직접 전화하세요.
(문자에 적힌 번호는 가짜입니다)

    [ 문자 지우는 법 알려주기 ]
```

## 6. 3분 타임라인과 발표 멘트

| 시간 | 화면 | 멘트 (요지) |
|---|---|---|
| 0:00–0:40 | 통계 슬라이드 | "2025년 1분기에만 3,116억 원이 사기로 사라졌습니다(경찰청 국수본). 60대 이상이 피해 1위(30.6%)인데, 기관사칭형 피해자의 52%는 30대 이하입니다. 그럼 경고는 누구에게 맞춰 만들어야 할까요? — 정답은 '그 사람'입니다." |
| 0:40–1:00 | 문자 수신 연출 | "지금 두 사람에게 똑같은 문자가 도착했습니다." (두 화면에 동시에 §3 문자 표시) |
| 1:00–2:00 | 분할 화면 비교 | "입력은 같습니다. 하지만 지훈 님에게는 요점 카드 한 장, 순자 님에게는 큰 글씨로 한 번에 한 걸음씩 — '놀라지 않으셔도 됩니다'부터 시작합니다." (왼쪽 화면 [다음] 눌러 단계 진행, 음성 낭독 시연) |
| 2:00–2:30 | 판별 근거 오버레이 | "형식은 달라도 판단 근거는 동일합니다 — 검찰은 문자로 통보하지 않는다, 링크는 악성앱이다. AI가 근거를 항상 함께 제시합니다. 금융위 AI 원칙의 설명가능성을 화면 그대로 구현한 것입니다." |
| 2:30–3:00 | 클로징 | "연령 타겟팅이 아니라 적응형 UX — 이것이 전 연령 안전망이 되는 방법이고, 저희가 코디세이에서 배운 '개인 속도 존중'의 금융 버전입니다." |

## 7. 운영 체크리스트

- [ ] 두 출력 모두 **사전 생성·캐시** — 심사장 네트워크 없이 재생 가능 (MVP 스코프 §3-3·§6)
- [ ] 왼쪽 화면 음성 낭독 볼륨 사전 점검 (발표장 스피커 유무 확인, 없으면 낭독 자막으로 대체)
- [ ] 뒷좌석 가독성: 왼쪽 화면 글씨가 3m 거리에서 읽히는지 리허설
- [ ] 문자 예시의 가상 표기(example 도메인·가상 번호) 유지 확인 — 실존 번호 절대 금지
- [ ] 진행 조작은 왼쪽 [다음] 버튼 2회가 전부 — 발표자 1인이 멘트와 병행 가능한 수준인지 리허설
- [ ] 백업: 전체 장면 화면녹화 영상 1개 (기기 고장 대비)

## 8. 베타 테스트 활용 (4050 AI Cafe)

같은 시나리오를 베타에서는 **블라인드 테스트**로 사용한다: 두 출력을 보여주고 "각각 누구를 위한 화면 같은가"를 묻는다. MVP 성공 기준 2번(10명 중 8명 이상 식별)의 측정 도구가 이 스크립트다. 추가로 60대 참가자에게는 왼쪽 화면만 단독 사용하게 하고 "다음에 뭘 해야 할지 알겠는가"를 관찰한다.
