부록 A — 용어와 아키텍처

금융 코디세이(가칭) — 전 국민 금융역량 인프라 구상 1단계: 금융사기 대응역량 훈련 체계 정식 명칭: AI 기반 전기통신금융사기(보이스피싱·스미싱) 대응역량 훈련 체계(시민 대상) · AI Fintech 텀 프로젝트 이 문서는 기획서 본문에서 자연어로 축약한 설계 정보를 원래 정밀도로 담은 참고 자료다. 기획서만 읽어도 이해되도록 본문을 쓰되, "그래서 컴포넌트가 정확히 무엇이고 지수는 어떻게 계산하는가"에 답하는 자리가 여기다.

1. 용어집

용어 정의
자극 유형(미끼 유형) 사기 시나리오가 사람을 움직이는 심리 지렛대. 권위(검찰·경찰·금융기관 사칭) / 공포(계좌 정지·수사 대상 통보) / 이득(저금리 대환·환급금·투자 수익) / 긴급(즉시 처리하지 않으면 불이익) / 친밀(가족·지인 사칭) 5종
발송(노출) 사용자에게 제시된 훈련 시나리오 1건. 열람 여부와 무관하게 센다 — 취약도 지수의 분모
열람 제시된 시나리오를 실제로 연 경우. 보조 지표(반응률)의 분자
피격(hit) ① 시나리오 속 링크 클릭 ② 정보 입력·전송 ③ 사기 시나리오를 "정상"으로 판정 — 셋 중 하나. 규칙 기반 채점으로 판정하며 취약도 지수의 분자
피격 지점 사후 분석 피격 즉시 훈련을 중단하고 걸린 지점을 단위별로 되짚어 보여 주는 화면. 실전 판별 모드의 근거 출력과 같은 컴포넌트를 공유한다
사전 행동수칙 교육 첫 훈련 전에 1회 제공하는 3분 이내의 행동 규칙 묶음. 사기 유형 지식이 아니라 행동 규칙이다
기관·지역 단위 집단(코호트) 집계 단위가 되는 사용자 집단(도입 기관·지역 등). 개인 단위 리포트는 제공하지 않는다
패널 고정 개선폭을 계산할 때 1회차와 N회차에 모두 참여한 동일 사용자 집합만 대상으로 삼는 규칙
전문 상담 연계 같은 자극 유형에 3회 이상 반복 피격된 사용자를 도입 기관의 상담·교육 인력으로 연결하는 절차
결정론 코어 같은 입력에 항상 같은 출력을 내는 일반 프로그램 영역. 훈련 진행·규칙 기반 채점·스케줄·저장·지수 계산이 여기 속하며 생성형 AI를 쓰지 않는다
서비스 3모듈 1단계 서비스의 구성 단위 셋 — ① 연령대별 기본 금융 교육(진입) · ② 금융사기 대응역량 훈련(핵심) · ③ 금융지원 제도 찾기(부가). ②의 콘텐츠 분류인 훈련 모듈과는 다른 층이다
연령대별 기본 금융 교육 모듈 ①(진입). 연령대의 금융과업에 맞춘 기본 항목(계좌이체·신용·금융문서 이해)과 행동수칙을 먼저 세우는 자리
금융지원 제도 찾기 모듈 ③(부가). 받을 수 있는 공공 지원제도를 조회·안내한다. 신청 대행·상담·중개는 하지 않는다
API 게이트웨이 훈련 트래픽이 서비스로 들어오는 단일 진입점. 인증·요청 제한·접근 기록을 한 지점에서 수행한다
외부 데이터 프록시 외부 데이터를 가지러 나갈 때만 경유하는 아웃바운드 조회 전용 통로. 내부망 직결이 없으며, 수집분은 AI 1차 검증 + 사람 검수 병행 후 적재한다

2. AI 레이어 — 5개 컴포넌트 명세

ID 명칭 적용 기술 입력 출력 선택 이유
A1 취약 자극 유형 진단(내부 명칭: 취약 자극 프로파일링) LLM few-shot 분류 + 규칙 기반 가중 스코어링 반응 로그(피격 여부·응답 시간·오판 유형), 시나리오 메타데이터 사용자별 취약 자극 유형 추정과 근거 요약 라벨링된 국내 학습 데이터가 없어 지도학습이 불가능하다. 소량 로그에서 유형을 읽어내는 일은 few-shot이 현실적으로 유일한 실행 경로다
A2 설명 난이도·다음 훈련 선택(내부 명칭: 적응 라우터) 설명 난이도는 LLM 프롬프트 주입, 다음 훈련 선택은 결정론 규칙 이해 수준(1~3), 취약 유형, 최근 회차 이력 해설 문안의 난이도·형식(단계별/요점 카드), 다음 훈련 후보 재작성은 생성 과제지만 무엇을 다음에 줄 것인가는 감사·재현 대상이다. 그래서 선택만 규칙으로 고정했다
A3 훈련 시나리오 자동 생성(내부 명칭: 시나리오 생성기) LLM + 슬롯 제약 템플릿 생성(사람 검수 후 배포) 자극 유형, 난이도, 실사례 코퍼스 변형 훈련 시나리오 문안 + 자극 유형 메타데이터 고정 문항은 반복 훈련에서 소진된다. 예고 없는 반복이 성립하려면 변형 공급이 전제다
A4 판별 결과에 실제 사례 근거를 함께 제시(내부 명칭: RAG 판별·근거 해설) 임베딩 검색 기반 근거 검색(RAG) + LLM 근거 생성, 규칙 필터 병행 사용자가 제출한 문자·화면, 실사례 코퍼스 판별 결과 + 유사 실사례 근거 + 위험 신호 목록 판별만 하고 근거를 못 대면 신뢰가 서지 않는다. 실사례를 함께 제시해 환각을 차단하고, 규칙 필터로 2차 방어한다
A5 쉬운 말 재작성·음성 안내(내부 명칭: 쉬운말 변환·음성) LLM 재작성 + Web Speech API 표준 해설 문안, 사용자 프로파일 쉬운 말 문안, 음성 안내 어휘 수준 재작성은 사전 매칭이 아니라 생성이다. 같은 경고를 상대의 어휘로 다시 쓰는 일에는 규칙 기반 대안이 없다

표 아래 본문·다이어그램에서는 자연어 명칭만 쓴다. 괄호 안 내부 명칭은 설계 문서와의 대조용이며 이 표에서만 병기한다. 폭이 좁은 자리에서는 A4를 실제 사례 근거 제시로 축약한다.

  • AI 필연성은 ②에서만 주장한다. ①의 이해도 점검은 정답이 있는 문항이므로 규칙 기반 채점으로 충분하고, ③의 제도 조회는 조건 필터로 처리한다.

AI 필연성 요약. ① 사기 수법은 생성형 AI로 매일 변형된다 — 고정 규칙·고정 문항으로는 훈련이 성립하지 않는다. ② 무엇에 약한지는 사람마다 다르고, 그 진단을 전 국민에게 1:1로 붙일 수 없다. ③ 같은 경고를 상대의 어휘로 다시 쓰는 일은 검색이 아니라 생성이다.

3. 결정론 코어 — 6개 컴포넌트 명세

ID 명칭 역할 왜 AI가 아닌가
C1 훈련 진행 관리(내부 명칭: 미션 상태기계) 훈련 진행 상태(시작·중단·완료·재시도) 관리 상태 전이는 정의된 규칙이며 창작 여지가 없다
C2 규칙 기반 채점 피격 여부 판정(링크 클릭·정보 입력·오판) 채점이 흔들리면 지수 전체가 흔들린다. 재현성이 최우선
C3 반복 훈련 일정 관리 간격 반복 큐 — 다음 시나리오의 도착 시점 관리 도착 시점은 정책이지 추론 대상이 아니다
C4 가명처리 프로필 저장 이해 수준·취약 유형·회차 이력을 가명처리해 저장 개인정보 처리 경로는 감사 대상이므로 결정론적이어야 한다
C5 안전 가드 실계좌·실거래·실개인정보로의 접근 차단, 생성 문안의 금칙 검사 안전 장치가 확률적으로 동작하면 안전 장치가 아니다
C6 모든 판정 이력을 기록해 추적 가능 시나리오·판정 결과·모델 버전 이력 기록 기록은 판단이 아니다. 사후 추적의 근거가 된다

취약도 지수는 규칙 기반 채점·반복 훈련 일정 관리·가명처리 프로필 저장의 출력만 입력으로 받아 결정론 코어에서 계산하고, 계산 이력을 판정 이력에 남긴다. AI 레이어는 지수 계산에 관여하지 않는다 — 기관에 제출하는 숫자를 생성 모델이 만들면 재현·감사가 불가능해지기 때문이다.

구분 흐름
요청 흐름 사용자 앱 → API 게이트웨이 → 결정론 코어가 훈련 모듈을 구성 → 필요한 시점에만 AI 레이어 호출 → 훈련 시나리오·해설 제공
AI 적용 취약 자극 유형 진단 · 설명 난이도 조정 · 훈련 시나리오 자동 생성 · 실제 사례 근거 제시 · 쉬운 말 재작성
AI 미적용 규칙 기반 채점 · 취약도 지수 산출 · 다음 훈련 선택 · 반복 일정 — 전부 결정론 코어가 수행한다
외부 데이터 수집 파이프라인이 외부 데이터 프록시를 경유해 조회 요청만 송신하고, 수집분은 AI 1차 검증 + 사람 검수 병행 후 저장소에 적재한다

왜 게이트웨이와 프록시를 따로 그리는가. 훈련 트래픽이 들어오는 문과 외부 데이터를 가지러 나가는 문을 각각 하나로 좁혀야, 안전 가드가 코드 안의 규칙이 아니라 구조 위의 경계가 된다 — 훈련 환경이 실제 금융 시스템과 분리돼 있다는 주장(금융안정성 원칙)은 이 두 지점에서 검증 가능해진다. 외부 데이터는 조회 요청만 나가고 응답은 AI 1차 검증과 사람 검수를 함께 거친 뒤 적재되므로, 훈련 시나리오의 근거 데이터에 검증되지 않은 외부 입력이 그대로 들어오지 않는다.

흐름 요약. 사용자의 모든 반응은 가명처리된 로그로 결정론 코어에 쌓인다. 코어는 필요한 시점에만 AI 레이어를 호출하고(진단·생성·판별·재작성), 판정과 지수 계산은 코어가 직접 수행한다. 기관에 나가는 산출물은 개인 기록이 아니라 기관·지역 단위 집단의 대응역량 리포트 하나다.

5. 금융위원회 AI 활용 7대 원칙 대응

원칙 본 서비스의 대응 대응 수준
거버넌스 모든 판정 이력을 기록해 시나리오·판정 결과·모델 버전을 추적할 수 있고, 다음 훈련 선택을 결정론 규칙으로 고정해 모든 개입이 재현·감사 가능하다 설계 반영
합법성 학습·판별 근거는 공공데이터와 공개 사례만 사용하고 개인 금융정보는 수집하지 않는다. 모의 사기 문자·전화의 실발송을 배제하고 앱 내 모의 수신함으로 한정해 정보통신망법 리스크를 회피한다 설계 원칙 수립 (법적 검토 진행 예정)
보조수단성 AI는 훈련·판별의 보조수단이며 최종 판단은 사용자에게 있다. 같은 자극 유형에 3회 이상 반복 피격되면 전문 상담으로 연계한다 설계 반영
신뢰성 실사례 코퍼스에서 검색한 근거를 판별 결과와 함께 상시 제시해 환각을 차단하고, 규칙 기반 필터를 병행한다. 채점은 LLM이 아닌 규칙이 수행한다 설계 반영
금융안정성 훈련 환경은 가상 격리되어 실제 금융 시스템에 대한 쓰기 접근이 없다. 링크를 누르거나 정보를 입력해도 실계좌·실거래에 도달하지 않는다 설계 반영
신의성실 금융상품을 판매·중개하지 않으며 특정 상품을 추천하지 않는다. 수익은 기관 대상 훈련 공급·성과 리포트에서만 발생한다 설계 반영
보안성 취약성 프로파일은 가명처리 후 저장하고, 개인 금융정보를 수집하지 않으며, 기관 제공 리포트는 집계 단위로만 산출한다 설계 반영

7개 전부에 대응이 있으나 대응 수준을 구분 표기한다. 합법성은 법적 검토가 끝나지 않았으므로 "설계 원칙 수립" 단계임을 숨기지 않는다 — 7개를 균질하게 주장하는 것보다 수준을 나눠 밝히는 편이 방어력이 높다.

6. 서비스 3모듈 구성

모듈 지위 하는 일 AI 적용 데이터 원천 현재 상태
① 연령대별 기본 금융 교육 진입(우선) 연령대별 기본 과업 항목과 행동수칙 4개를 먼저 익힌다. 이해도 점검은 정답이 있는 문항이므로 규칙 기반 채점으로 처리한다 설명 난이도·다음 훈련 선택 / 쉬운 말 재작성·음성 안내 공개된 공공 금융교육 자료(참조) · 연령별 피해현황 설계
② 금융사기 대응역량 훈련 핵심 5단계 반복 훈련 절차 · 대응역량 취약도 지수 산출 · 훈련 모듈 3분류(판별형·행동형·생활과제형) 다섯 컴포넌트 전부 경찰청 피해현황 · 공개 사례 설계 + 실습 프로토타입(정적)
③ 금융지원 제도 찾기 부가(생활 접점) 몇 가지 질문으로 받을 수 있는 공공 지원제도를 찾아 안내한다. 신청 대행·상담·중개는 하지 않는다 쉬운 말 재작성·음성 안내 행정안전부 공공서비스(혜택) 정보 설계

모듈 간 연결

방향 무엇이 전달되는가 왜
① → ② 연령대 · 기본 과업 이해도 진단 결과 ②의 초기 훈련 프로필(난이도·시나리오 유형 분포)을 정한다. 수칙을 모르는 상태의 실패는 학습이 아니라 좌절이다
② → ① 자극 유형별 대응역량 취약도 ①의 다음 학습 항목 순서를 정한다 — 커리큘럼을 사람이 짜지 않는다
③ → ② 사용자가 확인한 실제 제도 정보 기관사칭 시나리오의 판별 근거이자 생활과제형 훈련 모듈의 소재가 된다
③ → 재방문 즉시 실익(받을 수 있는 제도) 훈련만으로는 다시 오지 않는다. 다시 온 사람에게만 반복 훈련이 성립한다
  • 개인정보 단서: ③의 조회 이력을 ②의 시나리오 개인화에 쓰는 것은 별도 동의가 있을 때만 작동하며, 저장 시점부터 가명처리한다.
  • ①의 이해도 점검 결과와 ③의 조회 이력은 취약도 지수에 들어가지 않는다. 지수는 ②의 피격 ÷ 발송만으로 계산된다.

7. 훈련 모듈 3분류

아래 3분류는 모듈 ② 안의 콘텐츠 분류다 — 위 서비스 3모듈과는 다른 층이다.

유형 역할 생성 방식 예시 비중
판별형 주력 — 5단계 반복 훈련 절차의 본체 LLM 동적 생성(사람 검수 후 배포) 기관사칭 문자, 악성앱 설치 유도, 대출 빙자, 지인사칭 기관사칭형이 전체 피해의 51%(경찰청, 2025)이므로 기관사칭 비중 40% 이상
행동형 사전 행동수칙 교육 + 모의 이체 고정 템플릿 링크·번호 사용 금지 등 행동 규칙 학습, 모의 이체, 자동이체·해외송금 사칭 함정 변형 최소 — 첫 훈련 전 1회
생활과제형 진입 훅 고정 템플릿 + 공공데이터 "3분 만에 내 지원금 찾기" 진입 1회. 신청 동행은 범위 밖

첫 화면 원칙. 학습 소개가 아니라 지금 당장의 문제 해결 — "이 문자 사기인가요?" 판별과 "3분 지원금 찾기"를 앞에 둔다.

행동수칙 4개(사전 교육 내용). ① 문자 속 링크·번호는 쓰지 않는다 ② 확인은 공식 앱·대표번호로 한다 ③ 자금 이동 요구는 예외 없이 사기다 ④ 판단이 급할수록 한 박자 멈춘다.

8. 취약도 지수 — 상세 산식

8-1. 노출과 피격

용어 정의 비고
발송(노출) 사용자에게 제시된 훈련 시나리오 1건 분모. 열람 여부와 무관하게 센다
열람 시나리오를 실제로 연 경우 보조 지표(반응률)
피격 링크 클릭 / 정보 입력·전송 / 사기 시나리오를 "정상"으로 판정 분자. 규칙 기반 채점으로 판정

8-2. 개인 취약도

자극 유형 L(권위·공포·이득·긴급·친밀)별로 산출한다.

개인 취약도  V(u,L) = ( Σ wᵢ · hitᵢ ) ÷ ( Σ wᵢ ) × 100        (0~100, 낮을수록 안전)
가중치       wᵢ = 0.5 ^ ((r_now − rᵢ) / H)                      H = 반감기, 기본 3회차
피격 표시    hitᵢ = 1(피격) 또는 0(비피격)
산출 조건    유형 L의 누적 발송 n ≥ 3 일 때만 산출. 미만은 "측정 중"
보조 지표    반응률(u,L) = 열람 수 ÷ 발송 수 × 100
  • 최근 회차에 가중하는 이유는 문제 정의 자체다. 우리가 다루는 문제가 "시간이 지나면 감쇠한다"이므로 지수도 감쇠 가중을 쓴다 — 반년 전 결과와 지난주 결과를 같은 무게로 더하면 "지금 이 사람이 얼마나 위험한가"에 답하지 못한다.
  • 자극 유형 라벨은 AI가 붙이지 않는다. 시나리오의 자극 유형은 콘텐츠 제작 시점에 사람이 검수해 고정한 메타데이터다. AI는 "이 사용자가 무엇에 약한가"의 해석·추천에만 관여하고 지수의 분자·분모에는 관여하지 않는다.

8-3. 코호트(기관·지역) 집계

코호트 취약도  C(g,L) = 코호트 g 소속 사용자들의 V(u,L) 평균   ← 사용자 1인 1표
개선도(델타)   Δ(g,L) = C₁회차(g,L) − C_N회차(g,L)             ← 양수면 개선
최소 표본      |g| ≥ k 인 코호트만 산출·제공. 기본 k = 30
패널 고정      Δ는 1회차와 N회차에 모두 참여한 동일 사용자 집합에 대해서만 계산
  • 사용자 1인 1표인 이유 — 시나리오 단위 평균을 쓰면 훈련을 많이 한 소수가 코호트 지수를 지배한다.
  • 최소 표본의 이유 — 소규모 코호트 지수는 사실상 개인 식별로 되돌아간다. "집계 단위로만 산출한다"는 원칙의 집행 장치가 최소 표본이다.
  • 패널 고정의 이유 — 신규 유입자가 섞이면 구성 변화가 개선으로 오독된다.
  • 반감기 3회차와 최소 표본 30명은 근거 있는 상수가 아니라 운영 기본값이다. 도입 기관의 코호트 규모와 개인정보 정책에 따라 조정하며, 최소 표본은 상향만 한다.

8-4. 외부 지표와의 관계

과학기술정보통신부·한국인터넷진흥원의 기업 대상 모의훈련 지표는 "훈련 대상 인원 대비 열람·클릭 비율"로 발표된다. 우리 지수의 반응률 = 열람 ÷ 발송, 피격률 = 피격 ÷ 발송 구조는 이와 같은 계열이다. 다만 대상·채널·난도가 다르므로 두 수치를 직접 비교하지 않으며, 우리 지수의 목표치를 외부 훈련 수치로 제시하지도 않는다.

8-5. 서술 규율

  • 지수는 관측된 행동의 집계이지 예측 모델의 출력이 아니다 — "정확도", "예측"이라는 표현을 쓰지 않는다.
  • 근거 없는 목표 수치(예: "3개월 내 30% 감소")를 제시하지 않는다.
  • 실습 프로토타입은 판별 퀴즈형이라 제시 문항이 모두 열람되므로 반응률이 100%로 고정된다. 그래서 프로토타입 화면에는 피격률 기반 지수만 표시한다.

9. 금융역량 인프라 로드맵 — 상세 5단계

본 사업의 영역 축이다. ②~⑤는 계획·구상이며 시점·수치·기관명 확정을 담지 않는다. ④의 기관명은 예시이며 협의된 바 없다.

단계 무엇을 무엇으로 넓히는가 상태
① 금융사기 대응역량 훈련 체계(3모듈) — ① 연령대별 기본 금융 교육(진입) · ② 대응역량 훈련(핵심 — 취약 자극 유형 진단 · 5단계 반복 훈련 · 대응역량 취약도 지수) · ③ 금융지원 제도 찾기(부가). 세 모듈은 결과를 서로 전달한다 — (현재 설계·프로토타입 범위) 현 단계
② 금융역량 프로필 통합 — 1단계에서는 모듈 간 결과 전달까지이고, 2단계에서 세 모듈의 수행 결과를 하나의 금융역량 지수 체계로 통합해 기관 리포트에 반영한다 측정 축을 넓힌다 계획
③ 생애주기 금융과업 확대 — 1단계 ①은 연령대별 기본 과업까지이고, 3단계에서 취업·주거·퇴직 등 국면별 과업으로 확대한다 훈련 국면을 넓힌다 계획
④ 공공 교육 인프라 연계 — 디지털배움터·평생교육기관 등과의 연계를 검토한다 전달 경로를 넓힌다 구상
⑤ 전 국민 금융역량 인프라 — 금융회사의 금융소비자보호·ESG 프로그램 연계를 거쳐, 개인이 자신의 금융역량과 다음 과업을 지속 관리하는 상태를 향한다 도착점 구상
