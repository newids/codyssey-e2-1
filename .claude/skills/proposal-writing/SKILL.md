# Proposal Writing — 기획서 작성 규칙

## 형식의 주인은 미션 문서다

`docs/Mission-e2-1.md`가 요구하는 것 외의 형식 실험은 감점 요인이다. 최종 제출본 요건:
- **A4 인쇄 기준 2쪽 이내** (Markdown/Word/hwp)
- 필수 8항목: 문제 정의 / 타겟 사용자 / 서비스 개요 / AI 기술 적용 / 시스템 구성 / 기대 효과 / 향후 발전 방향 / 팀 역할 분담

## 지면 배분 (2쪽 기준 권장)

| 항목 | 배분 | 이유 |
|---|---|---|
| 문제 정의 (배경·선정 이유 포함) | 0.4쪽 | 심사의 첫 판단 지점 — 정량 근거 필수 |
| 타겟 사용자 | 0.25쪽 | 세그먼트 기준과 우선순위가 보여야 함 |
| 서비스 개요 (차별점 포함) | 0.35쪽 | 차별화 한 문장 + 핵심 기능 |
| AI 기술 적용 | 0.35쪽 | 기술명이 아니라 "왜 이 기술"의 표 |
| 시스템 구성 | 0.25쪽 | 다이어그램 1개 |
| 기대 효과 | 0.15쪽 | 정량 추정 우선 |
| 향후 발전 방향 | 0.15쪽 | 단계 로드맵 |
| 팀 역할 분담 | 0.1쪽 | 표 1개, 전원 기여 명시 (미션 필수 요건) |

넘치면 줄이지 말고 버려라 — 압축된 문장 12개보다 완전한 문장 8개가 읽힌다.

## 작성 규칙

- **정량 근거 병기**: 모든 통계는 기준 연도·출처를 붙인다 (예: "경찰청 국수본, 2025년 1분기"). 출처는 PROJECT_BRIEF.md의 팩트체크 완료 수치만 사용한다.
- **수식 표기 금지**: LaTeX/MathJax 금지 (프로젝트 규칙 — 모바일 가독성).
- **AI 기술 적용은 표로**: 기능 | 적용 기술 | 선택 이유 3열. "LLM 사용"이 아니라 "왜 규칙 기반으로는 안 되는가"가 드러나야 한다.
- **근거 없는 주장 금지**: 전략 문서에 근거가 없으면 `[TODO: 근거]`로 표기한다. 그럴듯한 수치 창작은 즉시 반려 사유다.

## 시스템 구성 (아키텍처) 표현 수준

- **설계 수준 다이어그램만** 작성한다: 컴포넌트 박스 + 데이터 흐름 화살표 (텍스트 다이어그램 또는 mermaid). 데이터 아키텍처(수집→저장→학습→서빙 흐름)를 포함하면 강해진다.
- MVP 코드 구현은 과제 범위 외다 — 아키텍처를 근거로 구현에 착수하지 않는다.
- 다이어그램의 각 컴포넌트는 "AI 기술 적용" 표의 행과 대응돼야 한다. 표에 없는 박스, 박스에 없는 기술이 있으면 정합성 결함이다.

## 개정 시 규칙

- 전면 재작성 금지 — 전략이 바꾼 부분만 수술적으로 고친다.
- 버전 규칙: 정본은 `Term-Project_기획안_v{N}.md`, 작업본은 `_workspace/03_proposal_draft.md`.
- 개정 후 자가 점검: ① 8항목 모두 존재? ② 2쪽 이내? ③ 모든 수치에 출처? ④ 다이어그램-기술표 대응? — 하나라도 실패면 제출 불가 상태로 보고한다.
